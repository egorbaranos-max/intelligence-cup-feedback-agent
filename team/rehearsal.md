# Живой прогон команды: доказательства вместо обещаний

**Внутренняя подготовка. Не прикладывать к конкурсному ответу как расширение лимита 15 000 знаков.** Тайминги ниже — наш тренировочный сценарий, регламент организаторов неизвестен. Все данные демонстратора синтетические, ответы «модели» подготовлены человеком. Qwen/ASR/VL и внешние API не запускаются.

## Четыре роли

**1 — ведущий/продукт:** формулирует проблему, читает исходные обращения и объясняет решение PM. **2 — оператор/архитектор:** запускает код и показывает только проверяемые поля. **3 — аналитик:** следит за счетчиками, Coverage7 и различием ресурса/денег. **4 — скептик/редактор:** засекает время, задает контрпримеры, записывает преувеличения. Имена участников пока не заданы. После первого прогона поменяться ролями: каждый должен уметь честно объяснить demo и экономику.

## Сначала проверить версию

Обновленные CLI и контрактные тесты demo проверены: 42 теста прошли. Отдельные финансовые тесты — другая группа. На защите важнее конкретные проверки, а не суммарный счет; перед прогоном запустить актуальную версию повторно.

В корне репозитория, Python 3.10+, без пакетов и сети:

```bash
python3 -m unittest discover -s demo -p 'test_*.py' -v
python3 -m demo --compact
```

Не сохранять результат как новые данные компании. Он не содержит вывода Qwen.

## Проверенная демонстрация за 90 секунд

Показывать читаемый фрагмент, не весь JSON. Секунды — ориентир репетиции. Ниже — реальные ключи локального CLI и проверенные ожидаемые значения.

| Время тренировки | Кто и действие | Что сказать / проверить |
|---|---|---|
| 0–12 с | 1 читает исходный №7: «Не приходит код-смс…» | «Вероятный сбой не превращаем в просьбу о новой функции. Дальше другой, синтетический пример, без модели» |
| 12–27 с | 2 запускает CLI: тикет, связанный звонок, второй тикет | `three_sources_two_episodes_blocked`: 3/2/2, recurring=false. «Публикация заблокирована: порог трех еще не выполнен» |
| 27–42 с | 3 показывает добавление четвертого источника, третьего эпизода | `four_sources_three_episodes_eligible`: 4/3/2, true. «Три эпизода, два клиента, прямое пожелание, окно 30 дней» |
| 42–55 с | 2 показывает потерю ACK и повтор | `mock_destination_cards_after_retry=1`. «Повтор оставляет одну карточку мока, реального трекера нет» |
| 55–68 с | 3 показывает удаление связанного звонка | `after_call_delete`: 3/3/2, true. Старая карточка отозвана (`old_card_retracted_before_regeneration=true`), затем пересобрана; связанный тикет сохранил эпизод |
| 68–80 с | 2 показывает удаление независимого эпизода | `after_episode_delete_below_threshold`: 2/2/2, false; `destination_cards_after_episode_delete=0`. «Порог потерян — карточка отозвана» |
| 80–90 с | 4 спрашивает об отрицании; 1 отвечает | «Точная цитата “Не хочу CSV” сама не проверяет смысл. Он требует независимой оценки настоящей модели» |

Проверены доверенное время эпизода `episode_at`, окно 30 дней, origin и авторство `speaker`: неизвестный episode_key не считается независимым, гипотеза/реплика поддержки не становится прямым пожеланием. Однако достоверность этих метаданных во входной системе еще предстоит установить. Демонстратор не измеряет Coverage7, качество Qwen или экономический эффект. Отдельный coverage_model.py проверяет только арифметику переданного независимого эталона.

Чтобы не листать длинный JSON, выполнить из того же корня репозитория:

```bash
python3 - <<'PY_DEMO'
from demo.case_contract_demo import run_demo
result = run_demo()
fields = ("raw_sources", "independent_episodes", "known_customers", "recurring")
for key, value in result.items():
    if isinstance(value, dict):
        print(key, {f: value[f] for f in fields})
    else:
        print(key, value)
PY_DEMO
```

Это та же функция, что в CLI; файлы не меняются. Для вопроса о цитате открыть полный `python3 -m demo`. Слайд карточки и речь использовать про «Хочу выгрузить заказы в CSV», не про другой неподписанный пример.

Если терминал не открылся, показать заранее просмотренный вывод как **сохраненный локальный результат**, не имитировать живой вызов модели. Не обещать доступ к корпоративным тикетам.

## Пять контрпримеров для скептика

Это не новые тестовые данные компании. Имена существующих тестов позволяют проверить точный смысл. Основной набор: `python3 -m unittest demo.test_contracts.ContractTests.ИМЯ_ТЕСТА -v`; проверки повторяемости/авторства: `python3 -m unittest demo.test_recurrence.RecurrenceTests.ИМЯ_ТЕСТА -v`.

| Контрпример | Ожидаемый ответ команды и проверка | Чего не говорить |
|---|---|---|
| **1. «Не приходит SMS»: отправим пожеланием?** | Заданный incident не входит в wish topic; без topic хранится анализ. `test_incident_does_not_enter_wish_delivery`. Дополнительно `test_hypothesis_does_not_enter_explicit_wish_topic` и `test_operator_or_unknown_voice_cannot_be_explicit_user_wish` | «Код сам понял, что это incident». Метку задает fixture; неверную смысловую разметку он не распознает |
| **2. «Не хочу CSV», а need — «хочет CSV»** | `test_honest_limit_exact_quote_does_not_prove_semantics` проходит именно как демонстрация предела: точная цитата есть, смысл неверен | «Тест зеленый, значит отрицание обработано правильно» |
| **3. Одинаковая фраза от двух клиентов; звонок+тикет одного случая** | `test_identical_text_from_different_clients_is_not_hash_deduplicated` сохраняет два эпизода; `test_call_and_ticket_of_same_episode_count_once_with_two_provenances` дает один. Связь эпизода доверенная, не угадана моделью | «Любой одинаковый текст — дубль» или «мы надежно определяем всех клиентов» |
| **4. Модель указала чужой продукт; затем отозвали доступ** | Чужой source/topic отклоняется, доступ повторно проверяется перед выдачей/доставкой: `test_guessed_foreign_topic_id_is_denied`, `test_access_revocation_between_queue_and_send_is_rechecked` | «Вся производственная безопасность доказана». Здесь простая продуктовая ACL в памяти |
| **5. После удаления приходит старое событие; TTL истек перед отправкой** | `test_deleted_source_cannot_be_resurrected_by_delayed_event` отклоняет прежнюю версию; `test_ttl_race_at_delivery_purges_and_prevents_send` не допускает отправку | «Все копии и бэкапы удалены навсегда». Проверены локальные структуры и мок; ID/версии остаются как метаданные |

Перед показом теста оператор в одной фразе называет ожидаемый результат. После — аналитик говорит, какую узкую гипотезу этот результат подтверждает. Запрещено переходить от зеленого unit test к заявлению о промышленной точности.

## Ответы и честное «пока неизвестно»

- **Где явные пожелания в семи примерах?** Не подтверждены. Это ограниченная отрицательная выборка, не доказательство отсутствия пожеланий во всем архиве. Синтетика не попадает в измерения.
- **Если в пилоте ноль повторяющихся пожеланий?** Coverage7=N/A. Показываем число тем и период, согласуем расширение наблюдения; не рисуем 100% и не генерируем спрос.
- **Как узнаем пропуски агента?** Люди независимо размечают полные продуктовые окна с предысторией и наблюдением после достижения порога, а не только найденные карточки.
- **Как подтвердим пользу PM?** Помимо доступной очереди смотрим решения, полезность, время и возраст нерассмотренных. Доставка не равна прочтению, реализации или прибыли.
- **Откуда 2760 часов?** Условный расчет чистой capacity всех ролей, после новой нагрузки. Исходная аналитическая работа неизвестна; если ее не было, ее экономия нулевая.
- **Откуда 2,986 млн ₽?** Условный PV gross-выгод за три года при независимом b=1,656 млн ₽/год, освоении 0,5/1/1, росте 6% и ставке 20%. Это потолок всех расходов; бюджет старта меньше на PV будущих расходов. Cash не выведен из часов. Без подтвержденного денежного потока потолок нулевой.
- **Что неизвестно до доступа в компанию?** Реальный поток и частоты пожеланий; активные часы; владельцы и права; надежность ID; параметры моделей; API источника/трекера; избегаемые платежи. Для каждого называем проверку: разрешенный снимок, замеры, реестр owners, проверка модели, финансовый реестр с владельцем выгоды.
- **Почему не правила/BI?** Сравнение обязательное. При том же результате выбираем более простой процесс. Один продукт проверяет осуществимость; причинное сравнение эффекта требует независимых команд.

Шаблон неожиданного ответа: **«У нас проверено X вот этим. Y пока неизвестно. Проверим его так-то до решения о релизе».** Если не помним число, сверяем материал; не создаем новое допущение голосом.
