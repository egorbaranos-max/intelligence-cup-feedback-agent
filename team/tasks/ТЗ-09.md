## ТЗ-09: README для жюри

Цель: переписать `README.md` так, чтобы эксперт понял решение за один экран, а инженер нашёл доказательства за второй.
Контекст: сейчас README открывается описанием ошибок прототипа и перечнем проверок. Если организаторы принимают ссылку на репозиторий, README — первое, что увидит жюри. Правила тона — CLAUDE.md, раздел 3, пункт 8.
Файлы: читать текущий `README.md`, `docs/solution.md`, `team/sprint-plan.md`; изменять `README.md`; старую версию сохранить как `docs/archive/README-v1-2026-11-03.md`.
Шаги:
1. Первый экран: одно предложение о решении, схема `docs/diagrams/data-flow.png`, таблица «что сдаём — где лежит» (4 строки), три цифры (1 000 обращений/день, 2 760 ч/год, потолок 2,986 млн ₽).
2. Второй экран: «Что уже проверено» — живые прогоны, протокол, калькуляторы, CI — по одной строке со ссылкой.
3. Третий экран: «Как повторить проверку за 2 минуты» — три команды.
4. Четвёртый экран: «Для команды» — ссылки на CLAUDE.md, EXECUTOR.md, sprint-plan, tasks.
5. Все фразы вида «не подтверждено» перевести в формат «что неизвестно → как узнаем в пилоте».
Критерии приёмки:
- Первый экран без прокрутки на ноутбуке содержит решение, схему и состав сдачи.
- Нет ни одной самоуничижительной формулировки без плана проверки.
- Все ссылки относительные и рабочие.
Проверка: открыть README на GitHub в приватном окне; `python3 scripts/verify_delivery.py --output artifacts/audit.json` зелёный.
Ограничения: факты экспериментов не приукрашивать; числа из assumptions.
Сообщить: диff по структуре «было — стало» в 5 строках.
