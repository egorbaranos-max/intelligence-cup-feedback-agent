# Разбор запуска run-11

На прежних 23 примерах Qwen3-4B проверена с отдельными схемами генерации для извлечения, проверки пожелания и сопоставления тем. Схемы ограничивают поля, типы и допустимые значения. Проверка принадлежности цитат, авторства, согласованности полей и смысла остаётся последующим этапам.

**На этом наборе результат полностью совпал с `run-09`, где использовалась общая JSON-грамматика.** Совпадают все объекты `results.jsonl`, итоговые карточки и очередь человеку. Все 23 извлечения допустимы с первой попытки; сделано 35 вызовов; 17 обращений требуют человека; две записи удержаны проверкой инструкций. Грубых совпадений с предварительными AI-метками — 13 из 23. Это не человеческая оценка точности.

Повторяющаяся CSV-карточка имеет те же четыре подходящих источника `syn-01/03/04/07`, три эпизода и двух клиентов. Пропуск `syn-02` как разовой операции, ошибочный класс в `case-04` и задержка полезного `syn-08` из-за цитаты чужой инструкции тоже сохранились. Подробности находятся в [разборе run-09](../run-09/postrun-audit.md).

Новые схемы не дали дополнительного улучшения на этих 23 текстах и не выявили регрессии их решений. Подтверждена работа схем в реальных вызовах и согласованность журнала этапов с выбранной схемой. Этот результат не переносится автоматически на новые данные: допустимый класс всё ещё может быть выбран по ошибке. Тексты уже были известны разработке; независимая оценка проводится отдельно после фиксации программы.
