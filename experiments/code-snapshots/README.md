# Точный код сохраненных запусков

Каждый ZIP содержит только Python-файлы, перечисленные в `code_sha256` соответствующего запуска. Внутри нет весов, окружения, токенов или обращений. `index.json` связывает архив с опытами и хранит SHA-256 самого ZIP и каждого исходника. Проверка не требует Git и работает в скачанной копии репозитория:

```bash
python3 scripts/verify_code_snapshots.py
```

Проверка сверяет архивы с исходными манифестами всех зарегистрированных опытов. Пропуск запуска, лишний файл или несовпадение байтов — ошибка. Общая команда проверки также выполняет эту проверку. Для двух самых ранних опытов, где еще не было поля `pipeline_version`, имя архива вычислено из уже записанных хешей кода; старые манифесты не изменялись.

Источники для исторических архивов: Git-история и сохраненная рабочая копия варианта run07. Файл `prompts.py` варианта run06 восстановлен из полностью сохраненного системного сообщения, исходного заголовка и неизмененных частей файла. Его SHA-256 побайтно совпал с первоначальным манифестом. Это восстановление исходника, а не изменение ответов модели. Ни один результат модели для подготовки архивов не редактировался.

Для воспроизведения распакуйте нужный архив в **новую отдельную папку**, установите версии зависимостей из манифеста опыта и передайте агенту исходный JSONL и манифест локально скачанной модели. Параметры, ревизия весов и дата `--as-of` записаны в опыте. Результат сохраняйте в другую новую папку. Изменение оборудования или библиотек может изменить генерацию даже при том же seed.

Архивы подтверждают доступность точных байтов исходников и согласованность записей. Они не являются независимым свидетельством личности оператора, факта исполнения или правильности понимания текста. Для проверки поведения нужно повторить запуск; для качества — независимо разметить новые данные.
