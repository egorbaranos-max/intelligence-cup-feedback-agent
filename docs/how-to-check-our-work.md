# Как проверить работу самостоятельно

На первом этапе команда отправляет ссылку на репозиторий. Эксперт должен понять решение без встречи с нами. Зеленая галочка GitHub показывает выполнение программных проверок; правильное понимание обращений и пользу для компании проверяют отдельно.

## Если нужно оценить решение без установки программ

1. Откройте [основной ответ в PDF](../submission/solution.pdf), [показатели эффективности](../submission/metrics.md) и скачайте [десять слайдов](../submission/presentation.pptx). Word также лежит в `submission/`. Это конкурсный ответ; остальные материалы не расширяют основной текст сверх лимита 15 000 символов.
2. Прочитайте [отчет о модельных опытах](../experiments/live_qwen/README.md). В нем сохранены неудачи: ложная тема в старом `run-02` и пропуск повторяющейся просьбы в `fresh_probe/runs/run-01`. Совпадение с предварительными ответами ИИ не является человеческим эталоном.
3. Для конкретной карточки проверьте исходные обращения, точные цитаты и число независимых эпизодов. Нужна проверка смысла: одна и та же цитата может быть ошибочно понята моделью. Пустая очередь может означать пропуск; большая — множество ложных тем.

**Итоговая независимая проверка на 48 примерах: результат будет внесен после завершения замороженного прогона.** До этого места нельзя подставлять результаты отладки старых примеров.

GitHub показывает HTML как исходный файл. Для интерактивного отчета или формы разметки скачайте **весь** репозиторий через Code → Download ZIP, распакуйте и откройте нужный `report.html` или `index.html` локально в браузере. Для чтения Markdown-отчетов на GitHub установка модели не требуется.

## Проверка файлов и программы без вызова модели

Нужен Python 3.10 или новее. На Windows/Linux используйте подходящую команду Python в терминале; файлы `.command` предназначены для macOS. Из корня распакованного репозитория:

```bash
python3 scripts/verify_delivery.py --output artifacts/my-audit-01.json
```

На подготовленном Mac можно открыть `Проверить_результат.command` двойным щелчком. Он выбирает установленный Python и создает новый отчет. При сбое показывает путь к JSON, если тот успел сохраниться. Для повторения команды вручную задайте новое имя, например `my-audit-02.json`: существующий отчет не перезаписывается.

Аудит выполняет четыре группы проверок: демонстратор программных правил; тесты прототипа и вспомогательных инструментов; целостность зарегистрированных модельных запусков; наличие и хеши документов сдачи. В итоговом JSON смотрите:

- `passed: true` и нулевые `exit_code` у всех групп;
- `stdout` и `stderr`: слово `skipped` означает, что часть тестов не выполнялась. Например, без необязательной библиотеки грамматики, указанного локального токенизатора или Node.js соответствующие проверки могут быть пропущены. Общий PASS не заменяет их выполнение;
- `revision_evidence`: хеши проверяемых исходников и документов до и после аудита, список изменившихся файлов и сведения Git, если это отдельный Git-репозиторий. Изменение проверяемых файлов во время аудита делает итог неуспешным: дождитесь завершения правок и повторите;
- для ZIP отсутствие Git и `no_repository_here` нормально: содержимое связывается с отчетом по хешам. Если архив распакован внутри другого репозитория, чужой Git HEAD ему не приписывается.

Хеши перечислены относительно корня проекта, поэтому их можно сравнить на другом компьютере. Область проверки указана в самом JSON. Записи экспериментов проверяются отдельно по своим манифестам и архивам кода. Хеши подтверждают неизменность файлов относительно записанных значений, но не удостоверяют личность оператора и истинность ответов модели.

Эта команда не вызывает Qwen, не подключается к компании и не измеряет денежный эффект. Успешный аудит программы не означает успешную приемку ИИ.

## Где увидеть настоящие вызовы модели

В папках `experiments/.../runs/...` находятся:

| Файл | Что он позволяет проверить |
|---|---|
| `calls.jsonl` | Отправленные сообщения и исходные ответы; у новых версий видны обе попытки при исправлении формата |
| `results.jsonl` | Проверки и решения по каждому обращению; ответ модели не подменяется итоговым решением программы |
| `cards.json`, `local-receiver.json` | Найденные темы и карточки у локального имитатора получателя |
| `review-queue.json`, `source-audit.json` | В новых версиях — источники для ручного разбора и судьба всех обработанных обращений |
| `manifest.json` | Реальная модель, ревизия, параметры, время, хеши кода и результатов |
| `evaluation.md`, `evaluation.json`, `report.html` | Проверяемый разбор; его выводы нужно читать вместе с ограничениями |

Старые версии могут не содержать более поздних журналов ручной проверки. Для точного повторения старого опыта используйте его [архив кода](../experiments/code-snapshots/README.md). Запуск текущего кода на прежних входах — новый опыт, а не повтор прежней версии.

## Новый запуск на своих примерах

На подготовленном Mac откройте `Запустить_проверку.command`. Он вызывает локальную Qwen на прежних 23 обращениях и сохраняет новый отчет в `artifacts/`. Это проверка работоспособности текущей версии на знакомых примерах. Для другого Mac сначала выполните [установку](live-experiment.md): нужны Apple Silicon, совместимое окружение, GPU Metal и скачанные веса. Текущий MLX-backend не является готовым запуском для Windows/Linux. Веса и Python-окружение не входят в репозиторий или ZIP.

Запуск уже скачанной модели не зависит от подписки на помощника в чате и не требует API-ключа. Первая загрузка зависимостей и весов требует интернета. Модель и параметры конкретного опыта всегда смотрите в его `manifest.json`.

Для проверки качества сначала придумайте новые разрешенные обращения и запишите ожидаемые ответы, затем запустите агент. Например: три независимые просьбы об отсутствующей функции, отказ от нее, сбой существующей функции, связанный повтор заявки и сообщение с двумя разными намерениями. Не копируйте отладочные фразы. Не меняйте правильный ответ после просмотра результата модели.

Сравните ложные пожелания, пропуски, неправильные объединения, отказы и объем ручной проверки. Новые настоящие обращения нельзя публиковать вместе с HTML и журналами без разрешения владельца данных.

## Деньги и доступ к сдаче

2760 часов и 2,986 млн ₽ — результаты условного сценария. Высвобождение времени само по себе не уменьшает выплаты. Без подтвержденных платежей или дополнительной маржи нет подтвержденной денежной выгоды. [Калькулятор](../tools/finance_model.py) позволяет проверить арифметику при других допущениях.

**Репозиторий сейчас приватный.** Обычная ссылка не дает экспертам доступ. До отправки владелец должен согласовать способ доступа с правилами этапа: приглашение экспертов либо разрешенная публикация. Затем открыть окончательную ссылку из отдельного аккаунта с правами эксперта; для публичного доступа — без авторизации. Проверка из аккаунта владельца недостаточна. Не публикуйте исходный PDF организаторов, веса моделей или корпоративные данные ради доступности ссылки.
