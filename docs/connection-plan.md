# К чему подключать агента

Есть два разных участника: помощник в этом чате, который помогает разработать проект, и код агента в репозитории, который должен работать в компании. Подписка на чат не является техническим требованием для запуска уже скачанной локальной Qwen.

## Что можно подключить сейчас

**Текстовый файл с разрешенными обращениями.** Прототип уже читает JSONL. Можно подготовить новые учебные примеры, сохранить их в файл и выполнить команду из [инструкции](live-experiment.md). Важно сохранить настоящую связь клиента, эпизода и даты; неизвестное оставить пустым. Сейчас это наиболее простой путь проверки.

**Человеческую разметку.** Два участника используют [локальную форму](../team/annotation-pack/index.html), третий согласует расхождения. [Процедура](training.md) готовит проверяемый учебный материал. Ответы не отправляются модели автоматически, поэтому можно сохранить независимую оценку.

**GitHub.** Он хранит исходники, документы и историю изменений. GitHub Actions проверяет код и файлы без запуска модели. Репозиторий не является подключением к базе обращений и не заменяет работающий сервер.

## Что потребуется от компании для настоящего пилота

| Подключение | Что нужно получить | Для чего |
|---|---|---|
| Система поддержки | Описание API или согласованный экспорт; доступ на чтение одного продукта; стабильные ID и события изменения/удаления | Читать обращения и не терять изменения |
| Внутренняя Qwen | Документация интерфейса, адрес внутри сети, служебная учетная запись, ограничения размера и частоты запросов | Заменить локальный MLX backend разрешенной моделью компании |
| Справочник продукта | Ответственный, доступные функции, терминология, актуальная версия | Отличать новую возможность от выполнения уже существующей операции |
| Корпоративные права | Кто может читать конкретное обращение, вложение и цитату; как узнавать об отзыве доступа | Не раскрывать сведения получателю без разрешения |
| Получатель карточек | Согласованный трекер или внутренняя очередь, API создания/обновления/отзыва, ограниченная служебная учетная запись | Доставлять и обновлять проверенные темы |
| Записи звонков и вложения | Разрешенные образцы, доступ к внутренним Qwen-ASR/Qwen-VL, правила хранения | Отдельно построить и испытать путь аудио/изображений |

Названия конкретных систем, адреса и форматы API из задания неизвестны. Подключения нельзя объявить готовыми до получения этих контрактов. Запрашивать полный доступ ко всем данным компании для первого опыта не нужно.

## Порядок подключения

1. Согласованный экспорт одного продукта, без автоматической отправки карточек. Разметка и исходные замеры.
2. Корпоративная модель и чтение новых обращений. Сохранение результатов для проверки уполномоченными людьми.
3. Тестовый получатель карточек, проверка повторной отправки, изменения источника, удаления и прав.
4. Ограниченная рабочая очередь с ручным подтверждением. Отдельный учет времени поддержки, владельца продукта и проверяющих.
5. Расширение только после выполнения критериев приемки. Обработка звонков и изображений допускается по своим результатам, а не по качеству текста.

Пароли и токены не нужно отправлять в чат или сохранять в репозиторий. Их размещают в согласованном хранилище секретов или локальном окружении; в документах достаточно имен переменных и описания доступа. Ограничение кейса на внешние LLM действует и при пилоте: корпоративные обращения нельзя отправлять внешнему ИИ-помощнику ради удобства разработки.

**Для первого этапа чемпионата эти корпоративные доступы не обязательны.** Сейчас нужно представить обоснованное решение и честные пределы локального опыта. Реальный пилот требует участия компании.
