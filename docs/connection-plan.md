# К чему подключать агента

Помощник в чате помогает разработать проект. Код в этом репозитории — отдельная программа, которая читает обращения и готовит карточки. GitHub хранит ее исходники и документы; он сам не подключается к поддержке и не запускает постоянный сервис.

## Что доступно сейчас

| Действие | Что требуется | Что получится |
|---|---|---|
| Прочитать решение и прошлые результаты | Доступ к приватному GitHub либо распакованный ZIP | Документы, журналы реальных вызовов и отчеты; установки модели не нужно |
| Проверить код и комплект сдачи | Python 3.10+ | Офлайн-аудит; пропущенные необязательные тесты отмечены в журнале |
| Повторить работу модели | Подготовленный Mac с Apple Silicon, Python-окружение и скачанные веса | Новый текстовый прогон и локальные карточки; [установка и команды](live-experiment.md) |
| Передать свои тексты | Разрешенный JSONL-файл с проверенными метаданными | Новые результаты; дату окна и ожидания задают до запуска |
| Подготовить человеческую разметку | Два независимых участника и третий для разногласий | Проверенные учебные примеры; [порядок работы](training.md) |

Формы HTML нужно открывать из локальной копии репозитория. На GitHub они отображаются исходным кодом. Неизвестные клиент, эпизод, время или автор остаются неизвестными: их нельзя заполнить вымышленными значениями ради красивой карточки. Для новых данных нужен собственный заранее подготовленный эталон, а не файл ожиданий старых 23 примеров.

На подготовленном компьютере скачанная модель работает без подписки на чат. Это не означает, что окружение уже установлено на компьютерах остальных участников. Веса и окружение не входят в ZIP. Для Windows/Linux нужен другой backend или отдельная среда с Apple Silicon; такой перенос пока не реализован.

## Что нужно от компании для настоящего пилота

| Подключение | Что нужно получить | Для чего |
|---|---|---|
| Система поддержки | Описание API или согласованный экспорт одного продукта; доступ на чтение; стабильные ID и события изменения/удаления | Читать реальные обращения и обновлять доказательства |
| Внутренняя Qwen | Адрес внутри сети, документация интерфейса, служебная учетная запись, лимиты, формат ошибок | Реализовать корпоративный адаптер вместо локального MLX-backend |
| Справочник продукта | Владелец, доступные функции, терминология и версия сведений | Различать новую возможность, обслуживание и неисправность |
| Клиент и эпизод | Проверенная связь тикета, звонка и вложения с одним случаем; устойчивые идентификаторы | Не считать связанный повтор новым независимым голосом |
| Корпоративные права | Разрешения на обращение, вложение и цитату; события отзыва доступа | Проверять разрешения при чтении, подсчете и передаче |
| Получатель карточек | Тестовая очередь или трекер с API создания, обновления и отзыва; ограниченная учетная запись | Испытать настоящую доставку вместо имитатора в памяти |
| Звонки и изображения | Разрешенные образцы, внутренние Qwen-ASR/Qwen-VL, правила хранения | Построить и отдельно проверить еще не реализованный полный путь |

Названия систем, адреса и форматы API из задания неизвестны. Контракты этих подключений еще предстоит получить и реализовать. Программный демонстратор прав и повторной доставки не является испытанием настоящей корпоративной системы.

## Порядок пилота

1. Согласовать разрешенный экспорт одного продукта, проверяющих и место хранения журналов. Собрать человеческий эталон и исходные замеры труда.
2. Реализовать доступ к внутренней модели и чтение обращений. Сначала сохранять черновики без рабочей публикации.
3. Проверить тестовый получатель: повтор запроса, потерю подтверждения, изменения и удаление источника, отзыв прав.
4. Запустить ограниченную очередь с подтверждением человеком. Учитывать время поддержки, владельца продукта и проверяющих, включая спорные и пропущенные случаи.
5. Расширять после приемки. Качество текста не доказывает качество аудио и изображений. Превышение лимита 25 сравниваемых тем, неоднозначные источники и срабатывания защитного фильтра пока требуют ручного решения.

Пароли и токены размещают в согласованном хранилище секретов или локальном окружении, а не в чате или репозитории. Корпоративные обращения по условию должны оставаться внутри компании; внешний ИИ-помощник не заменяет разрешенную внутреннюю модель.

**Для первого этапа чемпионата корпоративные доступы не обязательны.** Команде нужно предоставить доступную экспертам ссылку и проверяемое обоснование решения. Владелец приватного GitHub должен отдельно обеспечить доступ получателям ссылки. Реальный пилот, независимая разметка и доказательство денежной выгоды требуют участия людей и компании.
